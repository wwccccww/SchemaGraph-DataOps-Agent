# ADR-0001：核心架构决策

- 状态：Accepted
- 日期：2026-10-04

## 背景

项目需要同时解决复杂数仓 Text-to-SQL 的 Schema 召回断链、生成 SQL 的执行自愈，以及慢 SQL 的可验证改写。单纯扩大向量检索 Top-K 会显著增加无关 Schema 和 token，且仍可能遗漏没有业务语义的映射表。

## 决策

### 1. 图扩展

采用“Schema-RAG 种子表 + 1-Hop-per-Seed Junction 优先 + 受限最短路径兜底”：

- Junction Table 不能成为向量种子；
- Junction 距两个 Seed 各 1 hop，优先补充两个实体之间总长 2 edges 的映射路径；
- 未连通种子使用不超过 4 条边的最短路径连接；
- 最终不超过 12 张表和 3.5k Schema token。

不采用纯 1-Hop，因为它无法覆盖用户、订单、商品等 5～11 表长链；也不采用无限制全图最短路径，因为它容易引入无关表并失去上下文预算。

### 2. 双工作流

Text-to-SQL 和慢 SQL 诊断从入口分流，仅共享基础设施。前者输入自然语言，后者输入已有 SQL。禁止把慢 SQL 诊断作为每次问数的默认后处理。

### 3. 沙箱安全

采用 AST 门禁、最小权限 Role、只读事务、超时、资源限制和无条件回滚的纵深防御。SQLGlot 不作为最终权限边界。

### 4. 结果等价

以执行结果而非 SQL 字符串判定正确性。无序结果使用 Canonical Cell 行多重集；有限数值统一为精确 Decimal 表示，避免 BIGINT 精度损失和 CAST 假阴性。默认精确比较，只有用例显式声明时才应用数值容差。

### 5. 评测隔离

三套 Text-to-SQL 轨道分别报告：

- 自建电商 132 条；
- TPC-DS 派生 30 条；
- BIRD Complex 50 条。

另设 50 条慢 SQL 用例。不得把不同来源混合成单一准确率。

### 6. 指标状态

83%、96.8%、68.4% 等在系统评测前是 Target，不是 Measured。Measured 必须由固定版本评测任务和原始 JSON Log 产生。

## 后果

正面影响：

- 中间表召回来源可解释；
- 可通过消融实验量化图扩展贡献；
- SQL 执行具有数据库层安全边界；
- 自建与公开数据集的结论不会混淆。

代价与风险：

- 需要维护元数据、图和向量索引的一致版本；
- 3.5k token 和 12 表预算可能拒绝部分合法查询；
- BIRD 多方言需要适配层；
- TPC-DS 派生用例不能称为官方 TPC-DS 成绩；
- 性能指标对数据库快照和缓存协议敏感。
